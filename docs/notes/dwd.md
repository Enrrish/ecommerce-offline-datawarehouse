## 四、几个设计取舍，面试会问

**为什么 DWD 用内部表而 ODS 用外部表？** 外部表是对别人数据的引用，删表不能删数据；DWD 是 Hive 自己算出来的，删表就该连数据一起清，否则 HDFS 上会留一堆孤儿目录。

**为什么 price 用 DECIMAL(10,2) 不用 DOUBLE？** DOUBLE 是浮点近似值，`0.1+0.2 != 0.3`，金额累加会漂移。财务口径必须用定点数。

**为什么 category_id 用 BIGINT？** 源数据里有 `2053013554658804075` 这种 19 位数字，INT 上限约 21 亿（10 位），装不下会静默变 NULL。

**为什么 brand 空值留 NULL 而不是填 'unknown'？** NULL 表示"源数据没给"，'unknown' 表示"我判断它未知"，语义不同。填 'unknown' 应该在 ADS 出报表时做，不是在 DWD 破坏原始信息。现在 DWD 里 brand 为 NULL 的有 1,216,756 条（13%），category_code 为 NULL 的更多。

**为什么 ETL 里没有任何 WHERE 过滤？** DWD 层静默丢行是数仓大忌。上游一旦出问题（某天 user_id 全空），加了过滤你只会看到数字下降却查不出原因；不加过滤行数守恒，DQ 规则能立刻定位到"哪个字段空了多少"。过滤应该在 DWS/ADS 按业务口径做，而且要记录 drop_cnt。

**去重的 ORDER BY 为什么写"有品牌优先、有价格优先"？** 如果只写分区键，并列时取哪条不确定，重跑结果可能漂移。加了这个 tie-breaker，重复行里会稳定保留信息最全的那条。

## 五、踩到的坑

`SET hive.exec.parallel=true` 在 Hive 3.1.x 上会抛 `java.util.ConcurrentModificationException`（第一次跑就是这么失败的）。单条 INSERT 本来只有一条依赖链，并行也没收益，已显式关掉并在脚本里注明原因。这个坑你在简历上可以不写，但集群上遇到的每一个都值得记进笔记——面试问"遇到过什么疑难问题"时能说出具体报错和定位过程，比背概念有说服力得多。

另外验证了一件容易误判的事：抽样看到某行 `00:00:00`，我一度怀疑 CAST 丢了秒，实测 ODS 和 DWD 里 00 秒的都正好 1 条——那行本来就是整秒，CAST 没问题。**看到异常先验证再改代码**，这条对你以后排错很有用。

## 六、下一步 DWS

DWD 是"一行一次行为"，DWS 要做的是**按主题聚合**：用户日粒度、商品日粒度、以及漏斗。它和 DWD 的关键区别是引入了**业务口径**——比如 GMV 到底算不算 price=0 的 12,850 条、UV 怎么去重、加购转化率分母是谁。这些必须写进表注释，否则业务方一定会来问。
